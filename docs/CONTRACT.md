## 1. Critical Architectural Mismatch (BLOCKER)

**The frontend is NOT a Next.js app.** It is a single-page application (SPA) built with:

| Layer | Actual |
|---|---|
| Framework | **React 19 + Vite 8** (not Next.js) |
| Language | **TypeScript** (not JavaScript ESM) |
| Routing | Client-side via `window.history.pushState` / `popstate` |
| Entry point | `src/main.tsx` → `<App />` mounted on `#root` in `index.html` |
| CSS | Plain CSS in `src/styles.css` (not Tailwind v4 tokens; uses raw CSS custom properties) |
| Build | `vite build` → `dist/` (static bundle) |
| Server | None built-in; served as static files |

There is **no** `app/` directory, **no** Next.js App Router, **no** `lib/api.js`, **no** `lib/useRun.js`, **no** `lib/reduceEvents.js`, **no** `lib/chain.js`, **no** `lib/mock/` directory, **no** `components/` subdirectory, **no** `fixtures/` directory.

## 3. Data shapes in the frontend (the contract for backend responses)

Since the frontend currently uses only hardcoded data, these shapes are inferred from the TypeScript interfaces declared in `App.tsx`. The backend **must** serve these shapes.

### `AgentRun` (run object)

```typescript
interface AgentRun {
  id: string;                  // e.g. "tx_883a90c1f" (currently random-looking string; backend uses 8-char random)
  goal: string;
  status: 'running' | 'paused' | 'completed' | 'stopped'; // backend also has 'queued' | 'failed'
  verdict: 'verified' | 'partially_verified' | 'unverified';

  stepsBudget: { current: number; max: number };
  timeBudget:  { current: number; max: number };
  llmBudget:   { current: number; max: number };
  criteria: Criterion[];
  plan: PlanStep[];
  steps: RunStep[];
  created_at: string;          // display string, e.g. "2026-10-19 19:30 UTC"
  duration: string;            // display string, e.g. "48.2s"
  artifactContent?: string;    // markdown text
  incidentReport?: string;     // markdown text
}
```

### `Criterion`

```typescript
interface Criterion {
  id: string;

  check: 'min_urls' | 'word_range' | 'file_exists' | 'llm';

  status: 'pending' | 'pass' | 'fail';
  evidence?: string;
}
```

### `PlanStep`

```typescript
interface PlanStep {
  step_no: number;
```

## 4. API endpoints (what the frontend WILL need)

The frontend currently calls **zero** real API endpoints. All data is mock. To wire up a real backend, the following endpoints are needed. These shapes are derived from the frontend's data structures and from `AGENTS.md` section 9.

> **Note:** Because the frontend uses Vite (not Next.js), API routes cannot live in `app/api/`. They must be served by a separate Express (or similar) server, OR by adding a Vite dev proxy. In production, the static bundle is served separately and the API runs as its own Node process.

### `POST /api/auth`
Request: `{ code: string }`  
Response (200): `{ ok: true }`  
Response (401): `{ ok: false, error: 'invalid_code' }`  
Header: none required for this route.

### `GET /api/runs`
Auth: `X-Access-Code: <code>`  
Response (200):
```json
[
  {
    "id": "string",
    "goal": "string",
    "status": "queued|running|paused|completed|failed|stopped",
    "verdict": "verified|partially_verified|unverified|null",
    "createdAt": "ISO 8601 string"
  }
]
```

### `POST /api/runs`
Auth: `X-Access-Code: <code>`  
Request: `{ goal: string, budget?: object }`  
Response (201): `{ id: string }`  
Response (409): `{ error: 'run_active', message: string }` when a queued/running/paused run exists for the worker tag.

### `GET /api/runs/:id`
Auth: `X-Access-Code` OR `?t=<share-token>`  
Response (200):
```json
{
  "id": "string",
  "goal": "string",
  "status": "string",
  "contract": { "criteria": [] } | null,
  "plan": { "steps": [] } | null,
  "verdict": "string | null",
  "budget": { "maxSteps": 8, "maxSeconds": 180, "maxLlmCalls": 25 },
  "createdAt": "ISO 8601",
  "finishedAt": "ISO 8601 | null"
}
```

### `GET /api/runs/:id/events?after=<seq>`
Auth: `X-Access-Code` OR `?t=<share-token>`  
Response (200):
```json
{
  "events": [
    {
      "runId": "string",
      "seq": 1,
      "ts": 1234567890123.0,
      "type": "string",
      "payload": "{canonical JSON text}",
      "prevHash": "string",
      "hash": "string"
    }
  ],
  "status": "queued|running|paused|completed|failed|stopped"
}
```
Terminal statuses (polling stops): `"completed"`, `"failed"`, `"stopped"`.

### `POST /api/runs/:id/commands`
Auth: `X-Access-Code`  
Request: `{ kind: "pause"|"resume"|"stop"|"redirect", payload?: object }`  
Response (200): `{ ok: true }`

### `POST /api/runs/:id/chaos`
Auth: `X-Access-Code`  
Request: `{ tool: string, mode: "fail"|"slow"|"garbage", count: number }`  
Response (200): `{ ok: true }`

### `GET /api/runs/:id/verify-chain`
Auth: `X-Access-Code`  
Response (200): `{ ok: boolean, brokenAt: number|null, head: string }`

### `POST /api/runs/:id/tamper`
Auth: `X-Access-Code` (plus `ALLOW_TAMPER=1` env flag)  
Request: `{ seq: number, payload: string }`  
Response (200): `{ ok: true }`  
Response (403): `{ error: 'tamper_disabled' }` if flag not set.

### `POST /api/runs/:id/share`
Auth: `X-Access-Code`  
Response (200): `{ url: string }` (includes `?t=<HMAC-token>`)

### `GET /api/runs/:id/artifact`
Auth: `X-Access-Code` OR `?t=<share-token>`  
Response (200): file content with `Content-Disposition: attachment; filename="<name>"`  
Response (404): `{ error: 'no_artifact' }` if not yet written.

### `GET /api/runs/:id/bundle`
Auth: `X-Access-Code`  
Response (200):
```json
{
  "runId": "string",
  "events": [
    { "seq": 1, "ts": 0.0, "type": "string", "payload": "canonical JSON", "prevHash": "string", "hash": "string" }
  ],
  "head": "string (hash of last event)"
}
```

### `GET /api/health`
No auth.  
Response (200):
```json
{
  "ok": true,
  "db_reachable": true,
  "llm_reachable": true,
  "worker_alive": true,
  "version": "string"
}
```

## 6. Hash chain formula (for `/verify` offline verifier)

From `AGENTS.md` section 7 (`server/recorder.js`). Since there is no `lib/chain.js` in this repo, the backend hash formula becomes the sole reference:

```
hash = SHA256( prevHash + "|" + runId + "|" + seq + "|" + ts + "|" + type + "|" + payloadText )
```

Where `payloadText` is the canonical JSON string (sorted keys, no undefined values). The genesis `prevHash` is `"0".repeat(64)`.

The `/verify` page (not yet built) must re-implement this formula in the browser using `crypto.subtle.digest("SHA-256", ...)`.

## 7. Authentication

- Every route except `GET /api/health` and `POST /api/auth` requires `X-Access-Code: <ACCESS_CODE>` header.
- Share token: `?t=<token>` as a query param. Token is HMAC-SHA256 of `"<runId>.<expiry>"` using `SECRET_KEY`. Valid for 2 hours. Grants access only to the specific run it was created for.
- Constant-time comparison required for both the access code and the token.

## 8. Design token differences (frontend vs AGENTS.md)

The frontend CSS uses its own design token names (`--accent: #0E7C86`, `--bg: #F5F7FB`, etc.) which differ from AGENTS.md section 11 (`--color-accent: #0a0a0a`, `--color-bg: #f6f6f7`). The **frontend wins**. The backend does not produce CSS, so this is informational only.

Key differences:
- Accent color: frontend uses **teal `#0E7C86`**, AGENTS.md specifies **black `#0a0a0a`**
- Background: frontend uses `#F5F7FB`, AGENTS.md specifies `#f6f6f7`
- Font: frontend imports Geist, Instrument Serif, JetBrains Mono from Google Fonts; AGENTS.md says no external font requests
- The frontend uses `framer-motion` / `lucide-react` which are on the AGENTS.md reject list
